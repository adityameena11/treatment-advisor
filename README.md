# Treatment Advisor — AI Risk Console

A working, deployable AI-based personalized treatment advisor, scoped for a PBL-3
(3-credit) project. Two conditions — diabetes and heart disease — are each modeled by
comparing three algorithms (Random Forest, XGBoost, Logistic Regression) under 5-fold
cross-validation, with the strongest tree model deployed to production and explained
live using SHAP.

Three things set this apart from a typical prediction demo:

1. **Multi-model benchmarking**: every condition's model choice is backed by a
   cross-validated comparison table (accuracy, precision, recall, F1, ROC-AUC across
   3 algorithms) rather than a single untested pick — visible in the app under
   "view model comparison".
2. **A live what-if simulator**: dragging a slider recomputes both the prediction and
   its SHAP explanation in real time, rather than showing a static one-time chart.
3. **Confidence-aware escalation**: when a prediction sits close to the decision
   boundary (within 12 points of 50%), the app displays an explicit banner telling the
   user to rely on clinical judgement instead of the automated output — the system knows
   when it doesn't know.

Recommendations are also gated: a suggestion only fires when a clinical threshold is
crossed **and** SHAP confirms that factor is genuinely driving this specific patient's
risk upward, so the advice never contradicts what the model actually learned for that case.

## Project structure

```
project/
  backend/
    main.py            FastAPI app (serves predictions + explanations)
    train_model.py      Trains both models from the CSVs in data/
    requirements.txt
    data/                diabetes.csv, heart.csv (public datasets)
    models/              saved .pkl models + SHAP explainers (generated by train_model.py)
  frontend/
    index.html
    style.css
    app.js               calls the backend API; API_BASE is set at the top of this file
```

## Run it locally

**Backend**
```bash
cd backend
pip install -r requirements.txt
python train_model.py      # only needed once, regenerates models/
uvicorn main:app --reload --port 8000
```

**Frontend** — in a second terminal:
```bash
cd frontend
python3 -m http.server 8080
```
Open `http://localhost:8080` in a browser. The frontend is pre-configured to call the
backend at `http://localhost:8000`.

## Deploy it

**Backend → Render (free tier)**
1. Push the `backend/` folder to a GitHub repo (include `models/` — commit the trained `.pkl` files so Render doesn't need to retrain).
2. On [render.com](https://render.com), create a new **Web Service**, connect the repo.
3. Build command: `pip install -r requirements.txt`
4. Start command: `uvicorn main:app --host 0.0.0.0 --port $PORT`
5. Once deployed, copy the URL Render gives you (e.g. `https://your-app.onrender.com`).

**Frontend → Netlify or Vercel**
1. Open `frontend/app.js` and change the first line's `API_BASE` to your Render URL.
2. Push `frontend/` to GitHub (or drag-and-drop the folder into Netlify's deploy UI directly — no build step needed, it's static HTML/CSS/JS).
3. Deploy. That's it — Netlify/Vercel will serve `index.html` immediately.

**Alternative (single deploy, no CORS to manage):** put both frontend files under a
FastAPI `StaticFiles` mount in `main.py` and deploy the whole thing as one Render service.
Ask if you want this version instead — it's a five-line change.

1. **Lead with the model comparison table**, not just one algorithm. Explain that you
   selected Random Forest over XGBoost and Logistic Regression based on 5-fold
   cross-validated ROC-AUC, not by assumption — this is the single strongest thing to

2. **Demo the what-if simulator** — move glucose to 180 and watch the risk gauge and
   SHAP bars update live. Directly answers the "black box AI" criticism from your own
   report's §2.2.
3. **Demo the uncertainty banner** — pick values that land the risk near 50% (e.g.
   diabetes: pregnancies 3, glucose 135, blood pressure 76, skin thickness 28, insulin
   110, BMI 30, pedigree 0.5, age 38) and show the "low confidence, defer to clinical
   judgement" message appearing. This is a genuine, citable idea (uncertainty-aware
   clinical AI) and shows the system doesn't overstate its own reliability.
4. **Be upfront about scope**: Random Forest and SHAP on tabular data are established
   techniques, not new research. The contribution here is the interactive
   explainability loop, the SHAP-gated recommendation logic, and the confidence-aware
   escalation layered on top of them — say this plainly if asked about novelty.
